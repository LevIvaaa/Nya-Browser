# Как выпускается версия

Установщик собирается на Windows и вручную: ему нужна отрисованная в Chromium
графика, подпись и полтора гигабайта распакованного Electron. CI этого не
делает — он ловит всё, из-за чего установщик получился бы неправильным, до
того, как кто-то станет ждать сборку.

## Перед сборкой

```
npm run check
```

Это типы, тесты, словари против `en.json` и списка языков, 31 строка
установщика на каждом из 65 языков, генерируемые блоки `.nsh` на расхождение с
`LANGUAGES`, репозиторий на случайно закоммиченный токен и сборка. Ровно то же
самое гоняет CI на каждый push — но локально это минута, а не ожидание.

## Версия

Номер живёт в одном месте — `package.json`. Поднять его, обновить «Сделано» в
[roadmap.md](roadmap.md), закоммитить, **запушить** — тег релиза будет указывать
на то, что лежит в `main`, поэтому пуш идёт до сборки, а не после.

## Токен

Токен лежит в git-ignored папке рядом с деревом и попадает в инструменты только
через переменную окружения:

```bash
export GH_TOKEN="$(tr -d '\r\n' < 'не комить и не пуш/claude personal token.txt')"
```

Ни в команду, ни в файл, ни в лог он не попадает. `npm test` проверяет, что
ничего похожего на токен не отслеживается git-ом.

## Сборка и публикация

```
npm run release
```

По шагам это: создать релиз на GitHub, если его ещё нет → отрисовать графику
установщика и строки на 65 языках → собрать → упаковать NSIS → загрузить →
проверить, что всё загрузилось.

Первый шаг существует не просто так. electron-builder запускает по
publisher-у на артефакт, и если релиза ещё нет, оба решают его создать:
проигравший получает `422 already_exists` и падает — **после** того, как залил
установщик, но **до** `latest.yml`. Со стороны это выглядит опубликованным
релизом, а ведёт себя как отсутствующий: установленная копия узнаёт о новой
версии только из `latest.yml`.

Последний шаг — `npm run release:check` — за этим и следит:

```
  + NyaBrowser-1.0.4-setup.exe (104922727 bytes)
  + NyaBrowser-1.0.4-setup.exe.blockmap (111988 bytes)
  + latest.yml (349 bytes)
```

Три файла. Если хоть одного нет, обновление не доедет ни до кого, и команда
завершится с ошибкой.

## Если сеть оборвала загрузку

Стапятимегабайтный файл заливается небыстро, и обрыв на середине — обычное
дело. `npm run release` можно просто запустить заново: релиз уже существует,
электрон-билдер зальёт недостающее. Проверить, чего не хватает, не пересобирая:

```
npm run release:check
```

## Заметки к релизу

Описание релиза пишется руками на странице тега — что починено, человеческими
словами, без списка коммитов. Пока установщик не подписан, туда же идёт строчка
про предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае».
Про сертификат — [signing.md](signing.md).
