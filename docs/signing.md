# Подпись установщика

Установщик сейчас не подписан. Он работает, но при скачивании Windows
показывает синее окно SmartScreen «Система Windows защитила ваш компьютер»,
и чтобы установить браузер, человеку нужно нажать «Подробнее → Выполнить в
любом случае». Каждому. Каждый раз, пока репутация файла не наберётся.

Это единственный оставшийся долг, который **нельзя закрыть кодом**: нужен
сертификат для подписи кода, а его выдаёт удостоверяющий центр за деньги и
после проверки. Сборка к нему готова — ниже что купить и куда положить.

## Что покупать

| | OV (Organization Validation) | EV (Extended Validation) |
| --- | --- | --- |
| Цена в год | ~$200–400 | ~$400–700 |
| Проверка | документы организации или ИП | то же плюс усиленная проверка |
| Ключ | файл `.pfx` или облачный HSM | только аппаратный токен или облачный HSM |
| SmartScreen | предупреждение уходит **после** набора репутации | репутация с первой сборки |

С 1 июня 2023 года все сертификаты для подписи кода хранятся только на
аппаратном или облачном HSM: файла `.pfx` на диске больше не выдают.
Практически это значит одно из двух:

- **токен** (YubiKey и подобные) — подписывать можно только с той машины, где
  он вставлен; CI отпадает;
- **облачная подпись** (Azure Trusted Signing, SSL.com eSigner, DigiCert
  KeyLocker) — работает и локально, и в CI, обычно дешевле токена.

Для одиночного проекта разумный выбор — **Azure Trusted Signing**: около
$10 в месяц, работает из GitHub Actions, но требует организацию с историей
не меньше трёх лет либо индивидуальную проверку.

## Как подключить

electron-builder подписывает сам, как только видит сертификат в переменных
окружения. Ничего в коде менять не нужно.

### Локально, файлом `.pfx` (старый сертификат или самоподписанный для теста)

```powershell
$env:CSC_LINK = "C:\path\to\cert.pfx"
$env:CSC_KEY_PASSWORD = "пароль от контейнера"
npm run release:signed
```

`CSC_LINK` принимает и путь к файлу, и его base64 — второе удобно для CI.

### В GitHub Actions

Положите base64 сертификата в секрет `CSC_LINK`, пароль в `CSC_KEY_PASSWORD`
и прокиньте их в шаг сборки:

```yaml
- run: npm run release:signed
  env:
    CSC_LINK: ${{ secrets.CSC_LINK }}
    CSC_KEY_PASSWORD: ${{ secrets.CSC_KEY_PASSWORD }}
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### Токен или облачный HSM

Файла нет, поэтому подписывает не electron-builder, а внешняя утилита
(`signtool` с CSP провайдера, `AzureSignTool`, `eSignerCKA`). Нужен
`win.signtoolOptions.sign` — путь к своему скрипту подписи; см.
[документацию electron-builder](https://www.electron.build/code-signing).

## Что меняется в сборке

`npm run release:signed` — то же, что `npm run release`, плюс
`win.verifyUpdateCodeSignature=true`. Этот флаг заставляет автообновление
проверять, что скачанное обновление подписано **тем же** издателем, что и
установленная версия. Для неподписанных сборок он выключен (иначе обновление
просто не поставится), для подписанных обязателен: без него подмена файла
обновления не будет замечена.

Сборка сообщает своё состояние сама. Без сертификата:

```
  Authenticode: no certificate (CSC_LINK is not set).
  The installer will work, but SmartScreen will warn on every download.
```

С сертификатом:

```
  Authenticode: certificate configured, electron-builder will sign
```

## Как проверить, что получилось

```powershell
signtool verify /pa /v dist\NyaBrowser-1.0.4-setup.exe
```

Должно быть `Successfully verified` и ваше имя в `Signing Certificate Chain`.
Ещё быстрее — правой кнопкой по файлу → «Свойства» → вкладка «Цифровые
подписи»: у неподписанного файла этой вкладки просто нет.

## Про самоподписанный сертификат

`New-SelfSignedCertificate` даёт подпись, которая проверяется только на вашей
машине и только после ручного добавления в доверенные корневые. SmartScreen
она не успокаивает — для него самоподписанный файл ничем не лучше
неподписанного. Годится, чтобы прогнать сам процесс подписи и убедиться, что
сборка и обновление не ломаются, и больше ни для чего.
